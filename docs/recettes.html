Ajouter un paramètre

  1. Ajoutez une ligne dans modele/comportements.csv (un comportement) ou modele/donnees-2025.csv (une donnée observée). Remplissez la fiabilité et la source, et pour une hypothèse les colonnes min et max (la plage plausible utilisée par l’analyse de solidité). 
    migrantNairu;0,05;part;Immigration;Effet des arrivées récentes sur le chômage d’équilibre;…;hypothèse;OCDE (2023);0,02;0,1
  2. Ajoutez l’id à la liste de P = view([...]) (ou DATA) dans src/model/calibration.ts : il devient P.migrantNairu, typé.
  3. Utilisez-le dans sim.ts. Le test « chaque paramètre est utilisé par le moteur » échoue tant que ce n’est pas fait, et inversement un P.x absent des CSV lève une erreur au chargement.
  4. Citez-le dans la colonne parametres du lien concerné dans modele/liens.csv : les joueurs le retrouvent dans le graphe des causes.
  5. npm run docs : il apparaît dans le catalogue.

Jamais de « ; » dans un texte de CSV : il décale les colonnes. Utilisez une virgule.

Ajouter un levier

Exemple réel : softPower (rayonnement culturel et diplomatie).

  1. Le type : ajoutez softPower: number dans Policy (src/model/types.ts).
  2. La valeur de 2025 : softPower: 6 dans BASE_POLICY (calibration.ts). C’est aussi la valeur du rejeu, sauf si politiques-2000-2024.csv en donne une autre.
  3. Le mécanisme dans sim.ts, à la bonne étape (voir le moteur). Travaillez en écart à la référence (policy.x − REF.x) pour que la politique de départ reproduise l’année de départ. Une dépense doit être payée : 
    const plannedPublicGoods = g(… + policy.otherServices + policy.softPower - REF.softPower)
  4. Le curseur dans src/ui/levers.ts, dans le bon groupe : 
    { key: 'softPower', label: 'Rayonnement culturel et diplomatie', min: 0, max: 30, step: 0.5, unit: 'bn', hint: '≈ 6 Md€ par an…' }
    weight (1 par défaut) règle le coût en capital politique : un sixième de la plage coûte weight point. Mettez 1,5 ou 2 pour une réforme très contestée.
  5. Le graphe : une ligne dans variables.csv (bloc Leviers) et un lien par effet dans liens.csv, avec les paramètres qui le règlent.
  6. Un test dans sim.test.ts qui fixe le sens de l’effet (ex. « une culture forte accroît l’influence »), et vérifiez que la comptabilité boucle toujours.

Ajouter une variable suivie

  1. Ajoutez le champ à YearState (types.ts) avec un commentaire qui dit son unité.
  2. Calculez-le dans step() et ajoutez-le à l’objet state. S’il doit avoir une mémoire d’une année sur l’autre, ajoutez-le aussi à Carry et à initialCarry().
  3. Déclarez-le dans variables.csv et reliez-le dans liens.csv ; donnez sa valeur dans src/ui/nodeValues.ts pour que le graphe affiche son évolution.
  4. Pour l’afficher : un indicateur dans src/ui/indicators.ts (tableau de bord et courbes), ou une ligne dans un panneau de src/ui/Panels.tsx.
  5. Pour l’expliquer : la fenêtre « Pourquoi ? » (explain.ts) accepte toute fonction (s: YearState) => number.

Ajouter un événement

Les événements vivent dans EVENTS (src/model/events.ts). Le jeu les tire au sort chaque année ; le joueur ne les déclenche pas.

{
  id: 'heatwave',
  label: 'Canicule meurtrière',
  icon: '🥵',
  category: 'climat',                        // climat | economie | monde | societe | technologie
  summary: 'Six semaines au-delà de 40 °C…',
  effects: [{ heatShock: 0.6, unrest: 0.05 }], // un objet par année, à partir du déclenchement
  chance: (s) => odds(0.08, warming(s, 0.3)),  // s = la France de l'an dernier
  cooldown: 2,                                 // années avant de pouvoir revenir
}
  • Chaque facteur de probabilité a un nom lisible : add(libellé, valeur) s’ajoute, mult(libellé, facteur) multiplie. C’est ce que la fenêtre « Pourquoi cet événement ? » affiche au joueur ; un facteur négligeable est masqué automatiquement.
  • Les effets sont des champs de World : growth, oil, ecbRate, panic, demandShock, qe, climateAmbition, heatShock, unrest, productivity, migrants, conflict. Ils s’ajoutent au monde de l’année (worldAt). repeat(n, effet) pour un effet durable.
  • Un nouvel effet : ajoutez le champ à World (types.ts), à 0 dans world.ts et baseWorld(), et utilisez world.x dans sim.ts.
  • Préférez des probabilités qui dépendent de l’état du pays : ce sont elles qui font émerger des enchaînements (réchauffement → réfugiés → tensions → colère).

Ajouter un scénario

  1. Ajoutez une entrée à SCENARIOS (src/game/scenarios.ts) : récit, difficulté, année de fin, événements imposés, leviers verrouillés, objectifs. 
    objectives: [
  { label: 'Dette sous 115 % du PIB en 2035', when: 'end', get: (s) => s.debtRatio, op: 'below', target: 1.15, show: pct0 },
  { label: 'Taux à 10 ans toujours sous 4 %', when: 'always', get: (s) => s.rate, op: 'below', target: 0.04, show: pct },
]
    when: 'end' se juge à la dernière année ; 'always' chaque année, et un échec est définitif.
  2. Ajoutez une stratégie gagnante à WINNING dans src/game/game.test.ts. Le test vérifie que ne rien faire ne donne pas 3 étoiles, que la stratégie fait mieux, ne perd pas la partie et gagne chaque élection.
  3. Réglez les cibles : jouez la référence (simulate({ decisions: [], events: sc.events, until: sc.end })), lisez les valeurs, et placez les cibles entre « rien faire » et « bien jouer ».

Ajouter une idée reçue

Une entrée dans MISSIONS (src/ui/missions.ts) : la croyance, la décision testée (patch), les indicateurs à mettre en avant (focus), le mécanisme en quelques phrases et les limites du modèle. Les chiffres du verdict sont calculés ; le texte doit rester vrai quels que soient les paramètres, ou dire « dans ce modèle ».

Ajouter un programme économique

Une entrée dans DOCTRINES (src/ui/doctrines.ts) : un titre, un texte et un patch de leviers appliqué d’un coup (il coûte du capital politique comme toute réforme).

Ajouter un succès, une une, un conseil

  • Succès : { id, icon, title, text, check: (c) => … } dans ACHIEVEMENTS. c.states est la partie ; ne testez que states.slice(1) (l’année de départ ne compte pas).
  • Une du journal : headline() (headlines.ts) titre l’événement le plus marquant de l’année : une cascade de règles, de la plus grave (fin de partie, crise, élection) à la plus banale. Insérez la vôtre à son rang de gravité, avec un ton (good, bad, neutral).
  • Conseil : adviseDraft réagit à l’aperçu d’une décision (avec un poids : les plus graves passent devant), adviseState à la situation. Les conseils s’affichent dans le Conseil des ministres, en bas, sans décaler les curseurs.

Ajouter une fin de partie

  1. Ajoutez le nom à Ending (types.ts).
  2. Ajoutez la condition dans la cascade de l’étape 16 de sim.ts, avec un seuil lu dans comportements.csv (bloc « Fin de partie »).
  3. Décrivez-la dans ENDINGS (src/ui/endings.ts) : titre, texte et la chaîne de causes qui y mène.
  4. Testez qu’une stratégie extrême la déclenche et que la référence ne la déclenche jamais.

  • Une nouvelle mécanique doit être neutre à politique inchangée : travaillez en écart à la référence, et la France de 2025 reste identique.
  • Si le rejeu se dégrade, vérifiez qu’elle est aussi neutre en 2000 (donnees-2000.csv, politiques-2000-2024.csv) : une valeur de 2025 codée en dur casse souvent le rejeu.
