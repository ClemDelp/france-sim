🎛️ Modifier un paramètre, sans coder

Tous les chiffres et toutes les règles du modèle sont dans des fichiers tableur du dossier modele/. Vous pouvez les corriger, les sourcer, les discuter : aucune ligne de code n’est nécessaire. Cette page explique quoi modifier, comment, et comment proposer votre changement.

Le plus court chemin : essayez votre valeur directement dans le jeu (🧠 Le modèle → Tous les paramètres), regardez l’effet, puis proposez la modification sur GitHub depuis votre navigateur. Les tests automatiques vous diront si elle tient debout. Voir les trois façons de faire.

Les fichiers du modèle

Chaque fichier est un tableau : une ligne par paramètre (ou par année, ou par lien), des colonnes séparées par des points-virgules.

Colonne Valeur ici À quoi elle sert
id climateMigration Le nom technique, utilisé par le moteur. Ne jamais le changer (le moteur ne retrouverait plus le paramètre).
valeur 60 La valeur utilisée par le modèle. C’est généralement ce que vous voudrez modifier.
unite milliers/an par °C Dans quelle unité s’exprime la valeur. Respectez-la : « 0,6 » et « 60 % » ne veulent pas dire la même chose selon l’unité.
bloc Immigration Le thème, pour s’y retrouver (et filtrer dans le jeu).
nom, explication … Ce que voient les joueurs dans « 🧠 Le modèle ». Écrivez pour quelqu’un qui ne connaît pas l’économie.
fiabilite hypothèse mesuré une statistique officielle · estimé tiré d’études sérieuses, avec une marge · hypothèse un choix raisonnable faute de mieux. Améliorer une hypothèse est la contribution la plus utile.
source Banque mondiale… D’où vient la valeur. Indiquez l’organisme, le document et l’année.
min, max 20 ; 150 La plage plausible : les valeurs que des gens sérieux pourraient défendre. Elle sert à l’analyse « 🔬 Ce résultat est-il solide ? ». Facultative (sans elle, l’analyse teste ± 30 %).

Dans tranches.csv et entreprises.csv, une ligne porte une valeur par colonne de tranche (g1 à g5, des 20 % les plus modestes aux 10 % les plus aisés) ou de taille (pme, eti, ge).

Les règles d’or du format

  • Séparateur : le point-virgule ;. N’en mettez jamais dans un texte (explication, source) : utilisez une virgule. Un test le vérifie.
  • Décimales : la virgule (0,7). Le point est accepté aussi, mais restez cohérent.
  • Encodage : UTF-8, pour garder les accents. Les fichiers commencent par un caractère invisible (BOM) qui aide Excel : laissez-le.
  • Ne renommez pas un id, ne supprimez pas de ligne, ne changez pas l’ordre des colonnes.
  • Ajouter une ligne à comportements.csv ne suffit pas : un nouveau paramètre doit être utilisé par le moteur (un test le rappellera). Demandez à un développeur, ou décrivez le mécanisme dans une discussion (« issue »).
  • Les parts de la dette par détenteur (holderMonde, holderBce, holderAssureurs, holderBanques) doivent faire 100 %.

Façon 1 — Essayer dans le jeu (aucun outil, aucun compte)

  1. Ouvrez le jeu, cliquez sur 🧠 Le modèle, puis l’onglet Tous les paramètres. Cherchez le paramètre (par son nom ou son id).
  2. Tapez une autre valeur. Toute la partie se recalcule avec votre variante ; un bandeau violet indique qu’elle est active et montre son effet sur la croissance, le chômage, la dette et la pauvreté.
  3. Ouvrez l’onglet Face au passé (2000–2024) : la colonne « Avec votre variante » dit si le modèle reproduit mieux ou moins bien l’histoire réelle. C’est un argument très fort pour votre proposition.
  4. Jouez quelques années : le bouton 🔍 Pourquoi en est-on là ? de la une du journal et l’analyse 🔬 Ce résultat est-il solide ? (onglet Courbes) montrent ce que votre valeur change.
  5. Satisfait ? Dans Tous les paramètres, téléchargez le fichier modifié (bouton ⬇ comportements.csv, etc.). Il contient déjà votre nouvelle valeur.

Façon 2 — Modifier directement sur GitHub (dans le navigateur)

  1. Sur la page du dépôt, ouvrez le dossier modele/ puis le fichier voulu.
  2. Cliquez sur l’icône ✏️ (Edit this file). GitHub vous propose de créer votre propre copie si vous n’avez pas les droits : acceptez.
  3. Modifiez la valeur (et la source, la fiabilité, la plage plausible si besoin). Utilisez Ctrl+F pour trouver l’id.
  4. Cliquez sur Commit changes…, choisissez Create a new branch and start a pull request, écrivez un titre clair (« comportements : élasticité de la TVA 0,7 → 0,6, source Benzarti 2020 »), puis Propose changes et Create pull request.
  5. Les tests automatiques se lancent tout seuls. Vous pouvez aussi déposer directement le fichier téléchargé depuis le jeu : Add file → Upload files.

Façon 3 — Dans un tableur (Excel, LibreOffice, Google Sheets)

  1. Ouvrir : dans LibreOffice, choisissez « Jeu de caractères : Unicode (UTF-8) » et « Séparé par : point-virgule ». Dans Excel français, un double-clic suffit généralement ; sinon Données → À partir d’un fichier texte/CSV, origine UTF-8, délimiteur point-virgule.
  2. Modifier les cellules voulues. Ne touchez ni à la première ligne (les noms de colonnes) ni à la colonne id.
  3. Enregistrer au format CSV : « CSV UTF-8 (délimité par des points-virgules) ». Attention : un Excel réglé en anglais remplace les virgules décimales et les points-virgules ; vérifiez le fichier dans un éditeur de texte avant de l’envoyer.
  4. Proposer le fichier sur GitHub (Add file → Upload files dans modele/, en remplaçant l’ancien) comme dans la façon 2.

Trois exemples concrets

Corriger une donnée de 2025

L’INSEE publie un PIB 2025 de 3 010 Md€ au lieu de 2 990. Dans donnees-2025.csv, ligne gdp, remplacez 2990 par 3010 et mettez à jour la source. Les tests de calage vérifieront que la France de 2025 reste cohérente (déficit, chômage…).

Remplacer une hypothèse par une estimation

Vous connaissez une étude qui chiffre les migrations climatiques vers la France. Dans comportements.csv, ligne climateMigration : nouvelle valeur, fiabilite passée de hypothèse à estimé, source complète, et plage plausible (min, max) tirée de l’étude.

Mieux expliquer un lien du graphe

Dans liens.csv, la dernière colonne est l’explication affichée aux joueurs. Vous pouvez la réécrire librement. Changer le sens (+, -, ±) ou ajouter un lien est aussi possible, mais le graphe décrit le moteur : si le mécanisme n’existe pas dans le code, ouvrez une discussion pour qu’un développeur l’ajoute.

Écrire une bonne proposition

Titre : comportements — élasticité TVA 0,7 → 0,6

Pourquoi : l’étude X (Benzarti et al., 2020, American Economic Journal) estime
qu’environ 60 % d’une hausse de TVA est répercutée dans les prix en France.

Effet observé dans le jeu (variante) :
- inflation après une hausse de TVA : un peu plus faible
- rejeu 2000–2024 : écarts inchangés (inflation 1,2 pt)
- tests : ✅
  • Une proposition = un sujet. Plus facile à relire, à discuter, à accepter.
  • Une source par valeur. Une affirmation sans source reste une hypothèse : dites-le.
  • Dites ce que vous avez constaté dans le jeu et dans « Face au passé » : c’est ce qui convainc.

Prochaine étape : tester son changement.

Une question, une idée de mécanisme ? Ouvrez une discussion (« issue ») sur GitHub en décrivant ce que vous avez observé et votre source.
